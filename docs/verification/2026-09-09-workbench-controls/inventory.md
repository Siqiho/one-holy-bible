## 2. 语义约定

| 分类 | 含义 |
|---|---|
| `remove` | 现行实现没有独立能力（含键盘/无 hover 入口），删掉不丢功能；有独立能力或契约边界的不得标 remove |
| `merge` | 能力要留，展示入口应合并，不能只因长得像就当重复 |
| `demote` | 能力要留，不应占工具栏/卡片一级 |
| `keep` | 有独立对象、作用域或数据职责，应保留 |
| `defect` | 安全、可访问性、文案或防错问题；**不可冒充冗余** |
| `resolved` | 该表面现行源码已不成立；阅读台修复单独标注 |
| `unverified` | 本轮没有足够现行证据 |

优先级：`P1` 误触/不可见反馈/阅读对比；`P2` 密度与发现性；`P3` 抛光；`none` 保留或已解决项。

## 3. 双搜索专项（不能只凭并排外观）

| | 搜索卡片 | 搜索经文 |
|---|---|---|
| 对象 | 卡片 title/body/summary/source/type 等字段 | 圣经正文索引（CUV/KJV） |
| 作用域 | 只过滤**右坞**当前章/序资源；不过滤中央「卡片」模块，也不过滤左坞整理栈 | 整本 / 旧约 / 新约 / 当前书卷；译本 chips 另滤 |
| 触发 | 输入即过滤 | 点「搜索」或 Enter 才提交；清空输入会清已提交词 |
| 结果 | 右坞少显示卡片；输入框旁可见「N 张」 | 中央浮层，点结果跳经文并可打开对应译本模块 |

结论：历史「两个并排搜索框」说的是**展示重复与决策负担**，不是同一功能做了两遍。建议 `merge` 的是外壳（把过滤器放进右坞），不是删掉经文搜索。**清除卡片搜索入口当前已存在**（源码 5073–5083）；Codex 在桌面视口实际清除成功，**不能沿用旧评审「没有清除入口」**。空态文案仍误导，见 CD-07。

## 4. 处理顺序（只建议）

### 批次 A — 可直接整理的展示项（不碰保存/清空/复核/同步数据链）

1. 可评估精简当前 App 的一级「保存布局」入口，改为可见自动保存信号；**保留 `onSaveLayout` 仅在显式保存时调用，不得挪到每次 `changeLayout`**；存储失败要有可见反馈/重试。
2. 删除 `{English} study desk` 眉题。
3. 搜索待提交提示只留一处：标题已是短句「点击搜索更新结果」，完整句只出现一次，不要再写成同一整句贴了两遍。
4. 有 hover 的桌面可降低卡片常驻操作密度；**无 hover 设备保留可见操作入口，并保留键盘入口与 busy/失败态**。不要为了简洁隐藏全部触控操作。
5. 隐藏或删除禁用的「添加资源库」。
6. 区分 HTML/视频的明确演示占位与真实 typed 资源：只处理演示占位，**补渲染缺口，不得过滤真实资源或整个类型**。
7. 卡片搜索无匹配时改文案，不要写「当前经节还没有资源」。
8. 把刷新已有的可见 pill 扩成通用轻量提示，替代绝大多数 `sr-only` `setStatus`。

批次 A **不再**把交换按钮、顶栏拖高写成可直接删除。交换钮在仅有 PointerSensor 时须保留或先做等效键盘替代；拖高是真实尺寸调整，不持久化不能当冗余删。

### 批次 B — 交互收敛（低数据风险，仍可能改 localStorage 布局字段）

1. 卡片搜索下沉到右坞；工具栏只留经文搜索。
2. 「重置」降级到设置/溢出，并加确认（确认框本身还不写数据）。
3. 统一浮层：Esc + 外点；灯箱补 Esc 与焦点归还。
4. 默认主题（非 warm）焦点环提高到 warm 的双层方案。
5. 去掉未选中经文 `opacity: 0.72`，并提供取消选中或接受「始终有选中节」。

### 批次 C — 数据链事项（先设计确认与回归，再改产品）

1. **重置**：`resetLayout` → `changeLayout(defaultWorkbenchLayout)`，会清模块开关、分栏，以及左坞整理索引 `centerCardResourceIdsByBook`。
2. **删除 / 退回待复核**：工作台同步卡走 `unsyncWorkbenchResource` → `markWorkbenchCardReaderReturned` + `syncWorkbenchCards(..., "remove")`；本地卡只写入 `deletedResourceIds`。
3. **保存卡片文字**：同步卡走 `updateWorkbenchCardReview` + 项目同步 + 强制刷新；失败文案仍可能泄漏 `codex-v4`。
4. **刷新卡片**：`loadWorkbenchSyncedResourcePayload({ forceRefresh: true })`，随后会修剪失效整理引用和本地编辑草稿。
5. **三卡片区合并**（若将来做）：会改整理索引与「双击加入左侧」主路径；阅读台已是「跟随阅读位置」的资源流，**不要把阅读台方案直接拆掉工作台维护面**。

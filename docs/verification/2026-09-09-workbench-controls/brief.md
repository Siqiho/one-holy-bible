## 范围与方法

1. 完整盘点当前 Workbench 主工具栏、模块控制、搜索入口、设置弹层及相关卡片操作，按必要调用链检查保存、重置、模块开关/交换、双搜索、来源筛选、刷新卡片、状态反馈和阅读台切换；对 Reader 只做必要对照。
2. 对照历史评审画布和两个评审子会话、主对话的后续用户决定。逐条区分真正冗余、可合并展示、应下沉、应保留、非冗余缺陷、已经解决、尚无证据。两套搜索是否冗余必须检查对象、作用域和触发机制，不能仅凭外观判断。
3. 每项记录控件位置、当前行为、证据文件及准确行号、历史问题对应关系、结论、建议、优先级、依赖及回归风险。安全/可访问性缺陷不可冒充冗余，Reader 的改善不可直接认定 Workbench 同样修复。
4. 提供分批处理顺序，明确可以直接整理的展示项与涉及保存/清空/复核/同步的数据链事项；这里只建议，不实施产品变更。
5. Codex 并行用内置浏览器查看现行页面并补充现场证据。执行者不启动、重启任何服务，不使用外部浏览器；拿不到 UI 证据就标为源码判断或待验证。
6. 完成后新建 Cursor 独立 review 会话，重新核对源码与历史证据，特别查遗漏、误判、过期结论、行号和越界；Codex 汇总验收。

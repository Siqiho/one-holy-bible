# OHB 序章卡片经文映射设计

**日期：** 2026-07-14  
**范围：** OHB 66 卷中当前归入 `bookIntro` 序章的全部卡片  
**目标：** 为每张卡片选定同卷中一处最适合的主经文，使卡片从序章迁移到该经文，并在以后重新生成台账或同步项目时保持结果。

## 1. 已确认的数据基线

当前 Edit 工作台中有 3,032 张卡片带有序章导航归属，覆盖 66 卷：

- 2,429 张图片卡。
- 603 张文字卡，其中 549 张为研读本正式导论卡，54 张为因缺少锚点而回退到序章的普通释经卡。
- 3,032 张卡片当前都没有有效经文锚点。
- 当前项目同步载荷只包含其中 2,428 张图片卡；其余 604 张处于暂不同步状态。

实施范围是全部 3,032 张，不仅是当前界面可见的 2,428 张。

## 2. 用户体验原则

1. 每张卡片只有一个最优主经文，不在多处经文重复铺开。
2. 主经文默认必须位于卡片所属的同一卷。
3. 用户打开目标经文时，卡片应在该经文的卡片区出现，且卡片的跳转目标也应指向该节。
4. 这批卡片不应继续出现在序章。
5. 不修改卡片的文字或图片内容；本任务只调整导航归属和同步状态。

## 3. 映射决策流程

每张卡片先生成候选经文，再由 AI 按卷复核。候选优先级如下：

### 3.1 明确经文证据

优先使用卡片 ID、标题、摘要、正文或来源证据中明确写出的本卷经文。当出现多个引用时，优先选择：

1. 标题或 ID 中的经文；
2. 对应卡片主旨的经文；
3. 正文中首个被详细解释的经文，而不是顺带提到的交叉引用。

### 3.2 来源页上下文

对图片卡和图片转文字卡，使用同一 PDF 页或相邻页中已有锚点的释经卡建立页面上下文。如果同页横跨多段经文，必须同时核对图片标题和证据片段，不能只按页码距离决定。

### 3.3 内容与经文语义

当没有明确编号或稳定的页面上下文时，将卡片中的人物、地名、事件、重复关键词和神学主题与本卷经文比较，得出若干候选。候选生成器只负责缩小范围，不直接作为最终结果。

### 3.4 全书性导论卡

对“作者”“书名”“写作时间”“大纲”等无法和某一节完全等同的卡片，选择最能承载该信息的书内经文：

- 作者、收信人或写作缘起：优先选正文中自我介绍、呼召、开篇或写作目的所在节。
- 书名：优先选书名由来所对应的开篇词或主角首次出现的经文。
- 主题、关键主题和救恩历史：选择最集中表达该卡片核心命题的一节。
- 大纲和结构：选择全书结构中的转折点、纲领句或开篇节；不将整个章节范围全部绑定。
- 历史背景、时间和地点：选择正文中明示年代、王、地点或历史情境的经文。

### 3.5 置信与复核

每条映射记录候选方法、简短理由和置信等级：

- `high`：标题、ID 或源证据直接指向该节。
- `medium`：同页上下文与卡片内容一致。
- `low`：主要依赖全书主题或语义匹配。

所有卡片都要经过按卷 AI 复核；`low` 项必须显式确认理由，不能只保留算法分数。

## 4. 持久化设计

新增一份带 `` 的映射清单，作为序章迁移的单一可审计真相源。每条至少包含：

- `cardId`
- `bookId`
- `primaryAnchor`
- `method`
- `confidence`
- `reason`
- `reviewStatus`

映射清单不应依附于某一次带时间戳的台账目录，以避免下次重新生成时丢失。

Edit 加载卡片时应用该映射，得到：

- `primaryAnchor = 目标经文`
- `coverageRanges = [{ start: 目标经文, end: 目标经文 }]`
- `verses = [目标经文]`
- 映射成功时不再输出 `bookIntro`

原始卡片 ID 和原始来源字段保持不变，以便反向定位原 PDF 或 JSONL 行。

## 5. Edit 与项目同步规则

### 5.1 Edit 加载

- 在卡片读取后统一应用映射，不区分图片卡和文字卡。
- 只对映射表中明确存在的卡片更改导航，不改变其他卡片的现有行为。
- 对映射表中不存在的卡片 ID、重复 ID、跨卷锚点和无效经文立即报错。

### 5.2 文字卡同步分类

当正式导论卡或原先带 `intro` ID 的卡片已获得精确一对一经文范围后，应按普通经文卡处理，不能再仅因 ID 或旧风险标志而归为 `temporarily_unsynced`。

### 5.3 项目资源输出

- 项目同步脚本优先使用已应用映射的 `primaryAnchor` 和 `verses`。
- 有有效经文锚点时必须省略 `bookIntro`。
- `navigationPrimaryAnchors` 不得残留 `book-intro:<book>`。
- 同步元数据保留映射方法和复核信息，便于日志分析和回溯。

### 5.4 OHB 工作台导航

现有工作台在计算卡片归组时优先使用 `bookIntro`。实施后这批资源不应再输出 `bookIntro`，同时增加回归测试，保证具有经文锚点的卡片不会被序章字段抢占归类优先级。

## 6. 映射生成与审核产物

实施将产生以下可追踪信息：

1. 完整映射清单。
2. 按卷统计：卡片数、置信分布、映射方法分布。
3. 异常清单：无候选、多个同分候选、跨卷引用、无效经文和缺失源证据。
4. 复核日志：保留被 AI 改写的候选结果和理由。

以上新增文档或数据文件名均必须包含 ``；不使用无标识的临时文件。

## 8. 可观测性

批量映射和同步需输出结构化日志，至少包括：

- 读取的序章卡片总数及按类型分布；
- 生成、复核、应用和拒绝的映射数；
- 按卷和置信等级的分布；
- 映射前后 `bookIntro`、`primaryAnchor` 和 `verses` 数量；
- 同步前后卡片总数和排除原因；
- 无效卡片 ID、无效经文和异常跨卷映射。

日志必须足以判断某张卡为什么被映射到某节，而不只记录“处理成功”。

## 9. 测试与验收

### 9.1 单元与集成测试

- 映射文件语法和字段验证。
- 卡片 ID 覆盖率、唯一性和 3,032 张基线校验。
- 66 卷覆盖率校验。
- 目标经文存在性与同卷校验。
- 应用映射后 `primaryAnchor`、单节 `coverageRanges` 和 `verses` 一致。
- 应用映射后不再保留 `bookIntro` 或 `book-intro:*` 导航锚点。
- 已映射导论文字卡可正常同步。
- 未在映射表中的普通卡片保持现有行为。

### 9.2 全量数据验收

- 映射表正好包含 3,032 个不重复卡片 ID。
- 映射后原 3,032 张卡片的序章残留数为 0。
- 原有非序章卡片数量、ID 和导航不发生意外变化。
- 同步生成载荷中的目标卡都有合法经文锚点。

### 9.3 人工试用

至少覆盖：

- 旧约文字导论卡一张；
- 新约文字导论卡一张；
- 有明确经文的图片卡一张；
- 依赖页面上下文的图片卡一张；
- 全书性主题或大纲卡一张；
- 短卷、只有一章的卷书一张；
- 无效映射或缺失卡片 ID 的失败路径。

试用后必须读取并分析本次产生的日志，检查错误、异常时序、性能回退、缺失埋点和可疑信号。
